# 分阶段开发、留痕与考后接手计划

> 状态：项目协作策略。目标是在备考期间降低用户即时投入，同时保留考后真正理解与形成个人贡献的条件。

## 阶段 A：当前备考期——AI 主导实现

- 用户负责：明确项目目标、限制开发范围、确认关键成本和安全边界；无需现在学习全部技术。
- Codex 负责：根据路线图逐步实现、测试、记录、整理文档和演示步骤。
- 每次完成一个版本后，必须提交 `docs/handoff/Vx.x.md`，记录实际实现、代码入口、关键数据流、技术选型理由、测试命令与结果、已知问题、下一步任务。
- 可以记录决策，但未获得用户确认的技术选择标记为“AI 初选/待用户复核”，不冒充用户决策。
- 禁止连续堆积未经测试的功能；测试和安全门槛始终有效。**学习验收可以延后，功能验收不能省略。**

## 阶段 B：考试后——理解、复现与优化

建议按 V0.1 → V0.2 → V0.5 → V0.6 的实际实现顺序回顾，CourseRAG 毕设实验按学校时间表插入：

1. 运行项目，复现一个文档入库、检索、回答、引用的完整调用链。
2. 阅读 handoff 文档，定位真实入口函数、模块依赖和数据结构。
3. 复现实验并检查数据来源、模型参数、测试口径和结果可信度。
4. 独立完成至少一个核心修改，例如检索策略、分块配置、证据校验、工具参数校验。
5. 在证据支持下参与方案选择并记录 ADR：候选方案、实验依据、最终取舍、局限。
6. 为毕业答辩和求职面试整理“我实际负责的工作”，而非套用 AI 产出作为个人贡献。

## 贡献与证据记录模板

| 待填写 | V0.2 | 检索与引用实验 | AI / 用户 / 共同 | 计划 / 已完成 / 待验证 | 实验运行记录 |

仅在实际发生后填写具体“用户已完成”记录。Git commit 作者或使用 AI 的提示词本身，不足以证明用户独立实现全部代码。

## Codex 每轮结束的固定输出

- 本轮完成内容与未完成内容
- 代码变更及关键入口
- 实际运行的测试和结果
- 采用的方案、替代方案、尚待验证的假设
- 当前用户必须确认的事项（尽量少）
- 考后阅读与复现入口
- 本轮贡献归属记录

## 何时更新项目对外描述

- README 的“已实现功能”只列已经运行验证的能力。
- 简历与毕设说明只描述实际完成、能够解释和证明的工作；实验指标必须有原始结果。
- 个人贡献在考后真实完成优化、实验、架构决策或代码修改后再补充，不得回溯虚构。
