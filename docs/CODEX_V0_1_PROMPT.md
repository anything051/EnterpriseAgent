# Codex 开发指令：V0.1 最小可运行 RAG

> 在 V0.0 规划通过审查后，复制本指令交给 Codex 执行。不得将本文件本身视为已经实施 V0.1。

## 目标

基于仓库现有的 PROJECT_PLAN.md 与 docs/architecture.md、docs/roadmap.md、docs/data_design.md、docs/evaluation.md，开发 V0.1：最小可运行、可测试、保留来源元数据的通用 RAG 引擎。

## 执行要求

1. 首先检查仓库状态和开发环境，复核相关库当前官方 API、版本兼容性和许可证；对无法联网验证的内容标注风险。
2. 建立 Python 3.11 项目、依赖和 .env.example；模型推理与 Embedding 的接口分别配置，不提交 API Key。
3. 实现 PDF/Markdown 导入、文档 ID 与文件 hash、页码、可用的偏移位置、解析器版本及分块元数据。确保 Chunk 可以返回原始文档。
4. 使用 PostgreSQL + pgvector 实现基础 Embedding 入库与向量检索，设计可重复导入与清理机制。初期不做 BM25/Rerank。
5. 实现最小 FastAPI 接口：文档导入、问答、结构化引用返回；引用 ID 必须来自真实检索结果。
6. 准备少量合法可公开的示例文档和样例问题，验证正常问答、无依据问题、无效文件、重复导入与 scope 隔离。
7. 添加 pytest 测试、基础 Docker Compose 与 README 启动说明。尽可能运行测试，汇报真实结果。
8. 列出修改文件、执行命令、验证结论和遗留问题。

## 阶段边界

- **不要**实现 LangGraph、多智能体、Function Calling、SQL 业务工具、知识图谱、LoRA 微调。
- **不要**提前实现 V0.2 的混合检索、Rerank 或大规模引用校验。
- **不要**虚构实验数据、运行结果、工具能力。
- 不修改或删除现有规划文件的核心目标；如需变更，解释设计原因。
- 复用外部源码要保留许可与出处；密钥、口令不得入库。
- 遇到非关键实现细节自行选择合理方案并记录，无须为小问题中断任务。

## 验收

- 可重现文档导入 → 向量检索 → LLM 答案 → 真实文档来源引用的完整链路。
- 引用可验证 document_id、chunk_id、页码或章节元数据。
- 测试脚本能实际运行；若缺少 API Key/数据库则明确记录受阻项目及可执行的本地验收步骤。
- 交付文件清单、部署/启动指令、测试报告（只写真实结果）与下一轮 V0.2 的建议。
