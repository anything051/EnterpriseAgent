# 评测与实验方案

> 本文所有指标是**计划评测**，当前没有实验数据，不得填写虚构结果。

## 1. 总原则

- 建立独立开发集与保留测试集；优先人工标注问题、标准证据与可回答性。
- 记录模型名称/版本、温度、Embedding、分块、检索 K、索引、Reranker、提示词、数据集 hash、代码提交 SHA、随机种子、运行时间和环境。
- 对不同版本采用相同样本与可比较的资源条件。包含正确、跨章节、多证据、无答案、矛盾材料、表格/公式等样例。
- 记录每个样本的真实预测、引用、工具轨迹和判分，不只报告平均值。
- 评测结果分开呈现：检索层、答案层、引用层、系统效率层、Agent 层。

## 2. CourseRAG 对照实验

| 组 | 系统配置 | 目的 |
| --- | --- | --- |
| A | 基础向量检索 + 标准回答 + 基础引用 | 基线 |
| B | BM25 + 向量融合 + Rerank，其他不变 | 检索优化 |
| C | B + 细粒度证据定位和引用支持校验 | 可信引用增量 |
| D | C + 证据不足识别/拒答 | 拒答效果与可回答率权衡 |

为了避免混淆，可补充消融：B 不加 Rerank、C 仅校验不重生成、D 调整拒答阈值。A/B/C/D 不可将多项改动的收益简单归因为单一算法。

## 3. CourseRAG 指标

- **Recall@K**：在标注有 gold evidence 的可回答问题中，前 K 个候选是否至少命中所需的标注证据。多证据问题同时报告 all-evidence recall。
- **MRR / nDCG@K（可选）**：排序质量。
- **Answer correctness**：人工/规则/模型判分，明确判分标准；对数学/术语问答尤其谨慎。
- **Citation support rate**：被引用证据真实支持的可验证陈述占比；需明确按 claim 还是 citation 统计。
- **Citation precision/coverage**：正确引用数占比、具有有效支持引用的陈述比例。
- **Abstention**：无依据问题正确拒答率，同时报告可回答问题的误拒答率。
- **P50/P95 latency**：定义为服务接收问题至响应结束的耗时；另记录首 token 延迟（若模型支持流式）。
- **Token / cost**：区分输入、输出和模型价格假设（无法获得计数时标记缺失）。

不把 LLM-as-judge 分数当作无条件真实标签；抽样人工复核并报告一致性和误差。

## 4. EnterpriseAgent 实验

场景采用合成企业订单、商品、库存和业务制度文档，提供对应预期数据库结果/文档依据。

| 组 | 方案 | 关注问题 |
| --- | --- | --- |
| E0 | 单 Agent + 只读 SQL/API + 基础 RAG | 最小业务任务基线 |
| E1 | 单 Agent + 只读 SQL/API + Trusted RAG | 可信检索对报告的影响 |
| E2 | 多 Agent + E1 工具和证据能力 | 角色分工是否带来真实收益 |

指标：任务成功率、工具选择正确率、工具参数合法率、报告 claim 支持率、非法操作阻断率、P50/P95 延迟、Token/成本、工具异常恢复率。**多 Agent 不一定优于单 Agent**，实验应如实呈现质量与成本的权衡。

## 5. 数据集与统计

- 开发初期：建议 30–50 条可人工检查样例，以验证流水线。
- 正式毕设：视课程覆盖情况扩展至约 100 条或更多标注题，样本规模以导师要求与评测可靠性为准。
- 对可回答与不可回答题分层统计；跨章节、多跳、混合型、负例单独分析。
- 使用配对比较，报告绝对差异、逐例失败案例；重复多次运行时报告均值与波动。
- 任何数字必须由实际脚本和原始结果支持，README 不展示假设数据为真实结果。

## 7. 验收

- 同样配置可以重新执行并得出可比较结果。
- 指标公式和 gold evidence 定义公开。
- 引用支持率抽样人工审查，记录争议样本。
- 每次方案变更有实验记录，不以无来源百分比包装简历。
