# EnterpriseRAG 评测与实验协议

V0.0 冻结评测设计。样本收集、标注、执行和结果报告对应后续阶段。本文件中的组别、样本规模和参数是实验计划。

## 1. 数据集与标注

| 数据集 | 来源和覆盖 | 样本级验收依据 |
| --- | --- | --- |
| CourseRAG | 可公开分发的课程材料与自编中文文本。覆盖单段、多段、跨章节、术语、公式/表格、无答案、矛盾和过期资料 | 问题、课程/scope、任务标签、可回答性、标准答案、必须命中的事实项、每事实项允许的一组或多组证据 |
| EnterpriseAgent | 合成产品、订单、库存和制度文档，配同一时点的受控 API fixture | 输入与角色、任务类型、快照/时区、参考 SQL 预先生成的期望结果、政策证据、允许工具及参数/时间边界、预期报告结构 |
| 企业故障集 | 相同任务加固定超时、暂不可用、永久失败、无权限和错误响应场景 | 故障时间线、预期安全结果、应否重试、恢复条件与预算，逐次核对调用审计 |

每条样本至少有稳定 ID、数据版本、split、scope、输入及标签来源。文档 gold span 定位到原文版本、解析配置、单元和字符区间。SQL/API gold 定位到业务快照、预期字段、单位、聚合口径及可复查的查询/响应。每个不可回答样本标注预期理由，可回答样本明确多版本冲突时的适用条件。若依据应为多个片段，gold span bundle 记录必须同时支持的范围。企业报告的建议通过检查必要约束、依据和计算判分。

建议先收集约 30–50 题作为课程开发集，随后扩展到约 100 道独立保留题，具体规模按课程与导师安排以及分层覆盖决定。企业先覆盖纯数据、纯政策、混合和故障各类，再按成本调规模。按章节/文件族或任务模板族划分开发与保留测试 split，同源变体和相近改写放在同一 split。测试所需的源材料仍在各组相同的语料快照内。调提示词、Rerank 配置、拒答阈值只使用开发集。人工抽取双标样本、记录一致率与分歧，并经裁决固化测试标签。小样本或单评审限制进入结论。

## 2. CourseRAG 对照组

| 组 | 变化 | 主要比较 |
| --- | --- | --- |
| A | 精确向量检索 + 共享生成器 + 基础引用绑定 | 基础检索、正确率和可追溯性 |
| B | 同一向量分支 + 中文 BM25，经 RRF 融合加 Rerank | B−A 衡量组合效果。用 B 关闭 Rerank 的消融分析重排贡献 |
| C | B + 段落/原文跨度 + 逐事实支持性校验并记录状态 | C−B 比较定位有效率、支持性识别与校验开销。记录校验状态并保留同一草稿 |
| D | C + 证据不足或冲突的答案级拒答门槛 | D−C 比较正确拒答、误拒和覆盖率，展示质量与可回答率的取舍 |

共同约束固定语料、切分、Embedding、Chat/提示词、提供给生成器的 K 和上下文上限，顺序与替换策略随实验组定义。四组均执行引用 ID 绑定、作用域核验和空候选/无合法引用的基础保护。C 只加标记时，B 与 C 的原始答案正确率和原始引用支持率预期相同，另报告 C 校验判定的质量及其标记覆盖率。D 加入基于支持性与冲突的策略。需要区分 C 的验证与改写时另开消融，确保 D 与 C 使用同一上游草稿策略。B、C、D 共享排序，先在开发集设定 BM25 分词版本、融合参数、重排池和截断。固定 RAG 的输入语料快照与环境，再做配对差分。

## 3. 指标与计算口径

| 指标 | 计算 |
| --- | --- |
| Recall@K | 对可回答且有 gold 标注的问题，逐题计算「前 K 个候选覆盖的必要证据项数 / 标注证据项总数」，再作宏平均。证据项含候选替代 bundle，任一 bundle 的每个跨度均被同版本、同单元的候选范围完整覆盖则命中，允许多个候选合并覆盖 |
| Hit@K / 全证据覆盖率 | 前 K 命中至少一项 / 命中全部必要项的题数，分别除以同一有标注的可回答题数。固定报告 K=5、10，并记录阶段（融合前、融合后或最终排序） |
| 回答正确率 | 可回答题中所有必答事实正确且无重大矛盾的题数 / 全部可回答题。拒答和系统错误计为未答对。规则核对数值、单位和容差，其余用人工 rubric，同时保留逐事实分数 |
| 引用支持率 | 在具有至少一条引用的可验证陈述中，所引证据组合确实支持陈述的数量 / 这类陈述数。另报逐 Citation 精度以识别搭便车引用 |
| 引用覆盖率 | 具有有效支持证据的陈述数 / 所有已发出的可验证陈述数，缺引用计为未覆盖。另报来源解析有效率（成功定位的引用 / 全部引用） |
| 支持校验判定 | 对人工标注的陈述按支持、缺失、矛盾和不确定给出混淆矩阵。支持标签精度为经人工确认支持的数量 / 自动判为支持的数量。另报自动判为支持的陈述占比和相应人工漏检数 |
| 正确拒答率 / 误拒答率 | 对不可回答题明确返回证据不足或冲突拒答的数量 / 不可回答题数。对可回答题以相同拒答规则计算误拒答率。超时、错误和不确定标记单列。报告答题覆盖率和覆盖条件下的正确率 |
| P50/P95 延迟 | 用单调时钟记录服务收到请求至最终响应结束，含检索、推理、验证、工具与重试。报告全样本及成功子集的分位数和有效样本数，超时占比单列 |
| Token 与成本 | 同一题所有生成/验证调用累计 input、output、cached token（可得时），Embedding 及 Rerank 用量另列。按记录日期、模型、币种和计价单元汇总可计费用，评审调用费用单列。未知用量标记缺失并报告计数 |

零分母用 NA，随报告提供分子、分母和失败数。错误请求与拒答需可区分，缺失值不以零补齐。引用支持性判断证据能否推出陈述。Ragas Faithfulness 使用提供给生成器的上下文作近似判断，作为辅助指标。可另测「替换或遮蔽引用证据后答案怎样变化」以研究模型依赖，保持替换策略和条件对照独立，不从引用支持率推断模型因果归因。[Ragas Faithfulness](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/faithfulness/) · [引用正确性与忠实性研究](https://research.tudelft.nl/en/publications/correctness-is-not-faithfulness-in-retrieval-augmented-generation/)

## 4. EnterpriseAgent 对照与判分

| 组 | 配置 | 可比较问题 |
| --- | --- | --- |
| E0 | 单 Agent，仅合法 SQL/API 业务工具 | 关系型查询与固定业务 API 基线，混合任务若缺政策证据按缺失评分 |
| E1 | 单 Agent，E0 工具 + Trusted RAG | 同样任务和基础工具，检验加入文档证据对混合任务的影响 |
| E2 | Supervisor + Knowledge/Data/Report，沿用 E1 工具和证据策略 | 比较编排分工的任务成功率、故障恢复、延迟和成本 |
| 策略消融 | 在固定 E1 或 E2 内单独替换并行/串行计划、重试策略、工具路由 | 同源故障脚本与时间预算，记录改变的唯一变量和实际政策降级 |

各组固定快照、任务、角色、预算、Chat、输出 rubric 和工具数据。对 E1 与 E2 使用相同的工具能力与模型配置，同时记录实际总调用量。对比先报告总体，再按纯数据、文档/混合、故障与权限场景分层。

- **任务成功率** 以全部分配任务为分母。输出必须同时满足必要数值和政策证据、报告格式、权限与预算。权限测试的成功行为是按预期阻断，单独报告。
- **工具正确性**。必要工具步骤覆盖率为已按要求调用的步骤数 / 参考需要的步骤数，允许等价合法路径。参数合法率是通过类型和领域校验的工具提议次数 / 工具提议总次数。另报非法请求阻断率，并确认实际副作用为零。
- **报告支持性** 沿用引用支持率和覆盖率，分文档、SQL、API 来源核对。报告数值可按字段、单位和允许的舍入容差复算。
- **恢复率** 为在规定预算内完成任务的可恢复故障样本 / 注入的可恢复故障样本。另记录无效重试、恢复后重复执行、永久失败处理和可见部分成果。
- 延迟、Token 和成本沿用通用口径，增加工具调用数、重试次数及节点用时。策略比较可得出无差异、收益或退化。

## 5. 可复现执行和归档

- 固定代码 SHA、依赖锁、数据库及扩展版本、平台、硬件、数据哈希、解析/切分配置、索引、模型/供应商/可得版本、温度、随机种子、提示词哈希以及排序、阈值、预算和评分协议。API 模型无法固定版本或随机性的，记录可见的版本、执行窗口和返回标识。
- 各组对同一批题做配对比较。顺序固定或用记录过的随机顺序交错。缓存冷热与并发设置一致。重复运行时分别给出次数、组内波动、配对绝对差和有条件的 95% 配对 bootstrap 区间，报告实际基数。对模型评审盲化组别与顺序，人工抽检并公布分歧。小类样本只作描述统计。
- 运行器在 V0.3 实现。样本集包含 manifest、问题、标注规则与资料来源。运行产物为 `runs/<run_id>/config.json`、`samples.jsonl`、`metrics.json`、`failures.md`。逐例记录预测、候选、引用、工具轨迹、基准答案、分值、状态及判分理由。导出的结果能从逐例文件重新聚合，公开范围服从数据授权。
- 验收包含对同一逐例文件重复聚合、手算夹具断言、固定模型替身跑通 CI、真实模型独立运行后固化原始产物。结论和简历数字均链接到对应运行记录。


## 6. V0.3 开发集的评分实现

首轮开发集以 [manifest](../data/course_rag/evaluation/v0.3.0/manifest.json) 固定原文哈希、解析器及 10 道题的标签。必要事实由正反向正则匹配，gold bundle 允许同一文档、同一原文单元的多个 Chunk 拼合。检索阶段故障对有标注题计为未命中。覆盖条件下的正确率把不可回答题上的实际作答计为错误。

引用支持率按已绑定的 Chunk 与 gold bundle 比较。细粒度引文的偏移有效率单列，避免 C/D 的较短引文改变 B/C 共同的支持率口径。未被规则判定的引用陈述单列。首轮原始记录可回算引用文本、内容哈希和范围，有效来源在执行时还验证了版本和原文。后续版本的候选记录额外保存文档、版本、原文单元 ID 和解析配置，供离线交叉比对。

B/C/D 共享一次检索和生成，C/D 再共享同一次审阅。报告中的延迟为各组包含的实测阶段之和。错误纳入全样本延迟，错误后缺失的 Token 按可得性记录。组别错误可能来自同一个共享调用。语义审阅和问题覆盖的 Token 独立汇总。Ragas 仅作为上下文 Faithfulness 辅助指标，从既有回答与生成阶段的前五条候选单独计算。[运行报告与原始产物](evaluation_runs/course-dev-20261120/report.md)

## 7. V0.5 企业任务的评分实现

E0/E1 对照固定 4 个业务任务和 1 个权限任务。任务通过需提供所有预登记来源。SQL 复核绑定参数、整数分汇总、报告展示值和内容哈希。库存复核 HTTP 路径、返回字段、可用量及哈希。制度重开授权原文，检查文档、版本、原文单元、偏移和引用文本。每项有效证据须能关联成功的审计步骤。权限任务检查模型调用数为零、证据为空且返回拒绝记录，单列统计。[任务集](../data/enterprise_agent/evaluation/v0.5.0/cases.json) · [真实 E0/E1 运行报告](evaluation_runs/enterprise/enterprise-dev-20261120/report.md)

延迟统计纳入有响应的非权限任务，包含未完成样本，P95 采用最近秩。Token 仅合计供应商返回用量的样本，覆盖数保存在 `metrics.json`。离线复算使用逐例响应和保存的授权原文回查。此开发集用于闭环验收，自然语言变体和故障场景的独立统计留到后续版本。[复现命令](enterprise_agent_demo.md#复现-e0e1)

## 8. V0.6 多智能体与固定故障对照

E1 和 E2 复用 V0.5 的四个业务任务与一个权限任务，再加入一次库存超时和持续无效库存响应。两组使用同一模型、数据快照、工具验证及业务判分规则。E2 关闭重试组只执行两项故障任务。瞬时故障恢复分母为实际注入超时的样本，指派数另存。永久故障的安全保留分要求报告只含可复核的 SQL 与制度依据，并清楚标出缺失的库存。[故障清单](../data/enterprise_agent/evaluation/v0.6.0/faults.json)

延迟从发起任务请求计到响应返回，包含模型、工具和检查点开销。报告保存实际调用次数、重试与 Token 覆盖。未完成任务纳入耗时统计。进程退出后复用证据单独验收，使用同一个会话和运行 ID 对照 PostgreSQL 工具记录。[执行和复算](enterprise_agent_demo.md#复现-e1e2-与故障对照)
