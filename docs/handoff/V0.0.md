本阶段交付 [总体方案](../../PROJECT_PLAN.md)、[架构与目录](../architecture.md)、[阶段路线图](../roadmap.md)、[数据与证据契约](../data_design.md)、[评测协议](../evaluation.md)和[开源调研](../open_source_references.md)。当前从总体方案进入架构和数据契约，再按路线图开展 V0.1。目标链路是文档解析、原文切片、向量入库和检索、生成、引用绑定与原文读取。当前交付为设计文档，V0.1 的代码入口、数据库和模型连通性有待实现和验证。

## 决策与风险

- 用户明确双应用目标、共享核心、V0.0 的范围和交付物。Codex 初选轻量 Python 应用层、Python 3.11、pypdf、LangChain Core 与 PostgreSQL 17 + pgvector。完整平台 Fork 可加快界面搭建，但需要承担上游模型、部署和许可证维护。依赖版本由 V0.1 实测后锁定。
- 主要风险包括中文 PDF 的段落与坐标质量、供应商结构化输出和 Embedding 维度兼容性、评审偏差。采用页码与原文回退、真实模型探针、人工标注与配对比较处理。模型费用有待按实际配置与测量记录。
- 代码、部署、安全回归和模型实验属于后续版本。评测文档中的组别和参数是预定方案。

## 实际验证

- 执行 `git diff --check`，通过。使用本地 Python 脚本验证 Markdown 相对链接、八个阶段的验收段落、七个实验组及证据 JSON 示例。公开来源链接在调研时核对可访问。
- 使用 Mermaid 11.15.0 解析两张 flowchart，语法通过。浏览器渲染待确认。
- 执行 `uv pip compile`，指定 Python 3.11 与 `--only-binary :all:`。V0.1 候选依赖在 macOS ARM64 和 Linux x86_64 目标均解析出 55 个包。工作区默认解释器为 Python 3.15.2。安装后的依赖导入、PostgreSQL 扩展与真实 Chat/Embedding 请求尚待运行验证。
