## 决策与局限

- 用户指示继续既定阶段。Codex 保留原单智能体 E1 路由，另用一张 LangGraph 图实现 E2。主管由服务端按显式任务范围路由。数据和知识专员各有模型的工具调用。报告角色使用后端模板绑定验证后的结果，避免模型重写业务数值。没有修改现有 RAG 的检索、授权和证据验证逻辑。
- 会话由应用 ID、原角色和原令牌派生身份共同限定。并发开始、恢复和工具执行写入在同一 PostgreSQL 会话锁下串行化。同一运行 ID 和相同请求返回同一报告。模型只接收本会话的最近三条任务概要。令牌轮换后不会继承旧会话，本版本未提供账号映射或迁移工具。
- [状态迁移](../../migrations/enterprise_agent/006_agent_state.sql) 创建专用 schema。PostgresSaver 保存版本化、可序列化的节点状态。另用按会话、任务、业务快照、工具与参数计算的稳定执行键记录尝试和结果。已提交成功记录在恢复时复用。进程若在读取完成与结果提交之间退出，恢复可能重放这次只读查询。此保证依赖 V0.6 工具只读。
- 每个任务最多 3 次模型调用、6 条工具尝试，允许对少数瞬时故障重试一次。模型名额、工具尝试和重试开关随任务持久化。模型和工具共享原任务的 90 秒预算，数据库语句另有 5 秒上限。数据库持久化、重建连接和报告响应会增加 HTTP 总用时。超过原期限的任务保留已安全提交的结果。
- 当前是本地单站演示。生产部署、保留期、账号体系、跨进程工作队列和负载实测仍待验证。

## 实际验证

使用 macOS ARM64、CPython 3.11.15、PostgreSQL 17.12 / pgvector 0.8.7、Ollama 0.23.1、Qwen 3.5 9B、nomic-embed-text 768 维及固定 BGE INT8。库存为本机 HTTP 服务，业务数据为合成快照。

- `uv run --locked --extra agent --extra course --extra rerank pytest -m 'not live'` 在全新 Compose 数据卷通过 87 项，包含 7 项新恢复回归。验证子进程退出后复用成功记录、瞬时重试、永久故障、并发互斥、会话历史隔离、权限降级和预算持久化。锁文件、Compose 配置和 wheel 构建通过。
- Streamlit AppTest 连接真实 API 和模型，验证了三源报告、四角色顺序、会话历史和切换令牌后的隔离。
- 启动本机真实 API，在销售 SQL 证据提交后、图节点返回前使进程退出。新进程用同一会话和运行 ID 恢复，销售执行记录仍为一条，证据 ID 一致，最后生成三源报告。重复请求返回同一报告，制度查阅角色读取该会话返回 404。自动化复现入口为 `pytest tests/integration/test_agent_resume.py -k recovers_committed_tool`。[真实进程重启记录](../evaluation_runs/enterprise/enterprise-v06-restart.json)
- E1 与 E2 的常规任务均为 4/4，权限任务均为 1/1。单次库存超时中 E2 重试恢复，E1 与关闭重试组缺失库存来源。永久故障时三组均保留验证后的销售和制度依据。E1 和 E2 的 P50 分别为 18.20 秒和 17.80 秒，输入／输出 Token 分别为 5189／582 和 4645／510。这些数字仅描述固定开发集，共 16 条记录。[对照报告](../evaluation_runs/enterprise/enterprise-reliability-20261120/report.md) · [逐例记录](../evaluation_runs/enterprise/enterprise-reliability-20261120/samples.jsonl)
- 归档副本离线复算得到相同的指标、报告及失败说明，哈希和临时凭据排查通过。V0.5 已归档的 E0/E1 指标也能用当前代码原样复算。GitHub 托管 CI 待分支发布后触发。

## 考后接手与贡献

先用同一输入跑 E1 和 E2，沿报告中的执行键回查一条业务来源。再运行 [恢复集成测试](../../tests/integration/test_agent_resume.py)，检查退出前后同一条证据的 ID，最后从逐例记录重算故障对照。适合亲自尝试的改动包括加一条预算耗尽用例，或调整重试间隔并重新测量恢复率和时延。

| 执行者 | 状态 | 贡献与证据 |
| --- | --- | --- |
| 用户 | 已提供 | 指示进入下一阶段，提供路线、范围与协作要求 |
| Codex | 已完成 | 实现并验证本阶段会话、检查点、重试、状态图和评测流程 |
| 用户 | 计划考后完成 | 独立复现并提交一条故障样本或重试策略对照 |
