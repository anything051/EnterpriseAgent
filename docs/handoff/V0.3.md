## 决策与限制

- 用户指示进入下一阶段。Codex 选择 4 份自编课程资料和 10 道开发题，其中 6 道可回答。题目覆盖单事实、多段、精确标识、无答案、冲突、过期与部分缺失。事实规则由 Codex 编写，尚需独立人工双标，也需要保留集才能做正式效果比较。
- B/C/D 共用实际混合检索与生成，C/D 共用实际审阅。组别延迟按所包含阶段计算。原始运行保留候选与模型故障，模型错误计入错误，无法自动计费的用量标为缺失。
- 当前应用的 OpenAI SDK 与 Ragas 的 Instructor/jiter 依赖无法在同一锁文件下解析。辅助评审单设 [Ragas 环境](../../tools/ragas/pyproject.toml)，仅支持本机 Ollama，关闭 Ragas 遥测。依赖与模型结果分别记录。

## 实际验证和结果

使用 macOS ARM64、CPython 3.11.15、PostgreSQL 17.12 / pgvector 0.8.7，Chat 为本地 Qwen 3.5 9B，Embedding 为 nomic-embed-text 768 维，重排为固定 BGE INT8。配置文件记录模型摘录、锁、提示词和语料哈希。

- `uv run --locked --extra rerank python -m enterprise_rag.evaluation run --run-id course-dev-20261120 --seed 42` 写出 40 条记录。12 条组别结果发生结构化输出错误，其中一些来自 B/C/D 的共享调用。CLI 因此返回 1，逐例和报告均保留。
- 6 道可回答题中，向量 A 组 Recall@5 覆盖 5/6，混合 B/C/D 组覆盖 6/6。D 的规则正确率为 4/6，正确拒答为 1/4。过期规则题的回答复述历史限额并标注废止，但 API 返回了已回答状态，按协议计作不当作答。
- 一道已有回答的 LRU 题运行了 Ragas Faithfulness 辅助评估，结果为 1.0，使用量单独归档。它只说明该样本的回答被评审模型认为可由给定上下文支持，无法外推到其他样本。[Ragas 结果](../evaluation_runs/course-dev-20261120/ragas.json)
- `pytest -m 'not live'` 通过 65 项，四项真实模型回归亦通过。两个锁文件检查、wheel 构建和产物哈希验证通过。
- `summarize` 从归档副本重算并逐字节比对。复核修正三个边界口径：缺失排名计未命中，已作答的不可回答题计错，精细引文单独验偏移。Docker Desktop 的 Linux ARM64 容器验证了镜像构建、进程身份、健康检查与真实入库。GitHub 托管 CI 需在分支发布后触发。
