## 技术决策与限制

- 用户确认进入 V0.1 并沿用既定的数据、范围和验收协议。Codex 选择 pypdf、FastAPI、psycopg、pgvector 精确余弦和本地 Ollama 验收。OpenAI 适配器复用 LangChain。无需本地模型的云环境可单独配置 Chat 和 Embedding。
- PostgreSQL 保存内容寻址的原始文件、每个版本的原文、索引状态和 Chunk。选择同一数据库事务发布，省去首版独立对象存储和任务队列。Embedding 在事务外按批调用。并发请求可能重复计算向量，版本和索引提交保持幂等。历史与失败记录保留在库内，首版可用独立 Compose 环境隔离测试数据。后台清理、在线重新索引和数据库级多租户隔离属于后续工作。
- 向量维度、归一化策略、模型身份、解析器和切分配置参与索引指纹。Ollama 通过 `/api/tags` 检查 Embedding 模型摘要。其他供应商的模型修订由运行者提供并维护。更换配置后用新集合重建。
- 引用校验覆盖作用域、候选 ID 和原文跨度，返回 `support_status=unchecked`。V0.2 才比较混合检索并校验语义支持性。扫描 PDF OCR、坐标高亮、复杂表格和面向公开上传的沙箱仍有待实现。
- 没有复制第三方源码。组件版本锁定在 [uv.lock](../../uv.lock)。依赖许可见[开源调研](../open_source_references.md)。样例为项目自编中文资料和合成业务信息，ReportLab 仅用于制作 PDF，运行环境无需安装。

## 实际验证

验证环境为 macOS ARM64、CPython 3.11.15、Docker Engine 29.9.2、Compose 5.6.1、PostgreSQL 17.12 / pgvector 0.8.7，数据库以 `rag_app` 角色访问。

- `docker compose ... config --quiet` 与 `docker compose ... up -d --wait` 通过，迁移成功。通过真实数据库查询确认扩展版本和向量距离。单元测试与数据库回归覆盖两类解析、并发和重复入库、失败重试、旧版本、跨应用/集合隔离、错误响应与 OpenAI 协议替身。
- `RAG_RUN_LIVE=1 uv run --locked pytest tests/unit tests/integration --tb=short` 通过，38 项全部通过，包含 25 项单元测试、12 项数据库集成测试和 1 项真实模型测试。
- `RAG_RUN_LIVE=1 uv run --locked pytest -m live -o log_cli=true -o log_cli_level=INFO` 通过。Ollama 0.23.1 使用 `qwen3.5:9b` 和 `nomic-embed-text:latest`（768 维），完成两次真实问答、两次重复导入、两次原文读取和一次证据不足拒答。PDF 证据定位到第 2 页，Markdown 证据定位到盘点异常段落。
- 同次运行记录的三条 Chat 调用输入/输出 Token 分别为 254/26、405/26、328/5。这些是功能验收的逐问用量，尚无正式评测或成本结论。
- `uv lock --check` 和 wheel 构建通过。另从真实 Uvicorn HTTP 进程验证健康检查、OpenAPI 及授权空集合问答。
- 初测的 `qwen3.5:4b` 返回带尾随字符的 JSON，服务正确拒收并返回 502。改用经探针验证的 9B 后完成验收。OpenAI 路径通过协议替身验证，未调用云端端点。Linux 运行、复杂 PDF 表现和正式评测待后续验证。
