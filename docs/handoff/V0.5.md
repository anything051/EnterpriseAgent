## 技术决策与局限

- 用户指示按既有路线图继续。Codex 选择单个 LangGraph 状态图和三种固定业务工具。角色从令牌解析，服务端核对任务范围、工具名称、参数、调用 ID 和次数。OpenAI 适配器使用 `bind_tools`，Ollama 适配器使用原生工具协议。Ollama 缺省 ID 按原生调用顺序配对，重复或非法的显式 ID 会被拒绝。
- 销售使用 PostgreSQL 独立账号、只读事务、专用表和服务端 SQL 模板。运行时检查预期角色、危险角色属性、角色成员关系及关键表权限。库存只访问回环地址的固定端点，限制连接与读取超时、响应大小和结构。两个数据源均为合成演示，依照快照核算。[SQL 快照和角色迁移](../../migrations/enterprise_agent/005_business_snapshot.sql) · [库存样本](../../data/enterprise_agent/demo/inventory.json)
- 自然语言辅助模型选择工具，报告由后端根据验证后的字段和原文渲染。V0.5 只支持既定模板和固定制度主题。制度引用是可信原文的逐字引用，安全边界是授权范围、批准正文与偏移检查。应用通过独立应用 ID 复用共享检索、索引与证据类型。
- 单任务最多 3 次模型调用、6 条工具提议，等待上限为 90 秒。未完成的只读调用会在自身超时内退出。应用在任务预算到期时丢弃迟到结果并返回此前已验证的部分报告。单进程共享 4 个执行线程，忙时返回受控状态。模型和工具失败按步骤记录。常规测试覆盖超时、错误响应、权限、预算、回查及 UI 换角色。
- 当前使用本机令牌与可信演示数据。真实云端 OpenAI 工具调用未验证。成本只记录可得 Token。多智能体、会话持久化及可恢复重试属于 V0.6。[路线图](../roadmap.md#v06-多智能体与可靠性)

## 运行与测试

使用 macOS ARM64、CPython 3.11.15、PostgreSQL 17.12 / pgvector 0.8.7、Ollama 0.23.1、Qwen 3.5 9B、nomic-embed-text 768 维及固定 BGE INT8。库存来自本机 HTTP 服务。

- `uv run --locked --extra agent --extra course --extra rerank pytest -m 'not live'` 在全新 Compose 卷上通过 80 项，其中 9 项为 EnterpriseAgent 回归。已有测试卷重跑 `005_business_snapshot.sql` 通过。依赖锁、wheel 构建及 Compose 配置检查通过。
- 首轮权限检查的测试夹具失败时显示了临时数据库连接串。已轮换该临时密码，并用脱敏类型包装夹具。回归以角色和 schema 权限检查证明只读连接访问不到 RAG schema。
- 本地模型通过原生工具协议返回三类真实调用。Streamlit AppTest 连接真实 API，核对销售额 ¥1,450.00、A100 可用 13 件和 24 小时制度原文，并测试重开原文及换角色后清除先前报告。
- 固定开发集含 4 个业务任务和 1 个权限任务，共执行 10 条组别记录。E0 完成 1/4，E1 完成 4/4。E0 的 3 个未完成任务均缺制度证据。SQL 覆盖均为 3/3，API 均为 2/2，制度从 0/3 变为 3/3，越权任务均按预期阻断。样本少且两组实际执行的操作不同，延迟仅描述本次运行。[运行报告](../evaluation_runs/enterprise/enterprise-dev-20261120/report.md) · [逐例记录](../evaluation_runs/enterprise/enterprise-dev-20261120/samples.jsonl) · [失败案例](../evaluation_runs/enterprise/enterprise-dev-20261120/failures.md)
- 在归档副本离线执行 `summarize`，指标、报告和失败说明与原文件逐字节一致。归档 SHA-256 和临时凭据排查通过。GitHub 托管 CI 待分支发布后触发。
