## 实际交付与调用链

启动、迁移及演示命令见 [CourseRAG 本地演示](../course_rag_demo.md)。

| 功能 | 入口与调用链 | 输入与产出 |
| --- | --- | --- |
| 课程目录 | [Streamlit 工作台](../../src/enterprise_rag/apps/course_rag/ui.py) → [课程 API](../../src/enterprise_rag/apps/course_rag/api.py) → [CourseCatalog](../../src/enterprise_rag/apps/course_rag/catalog.py) | 课程、章节、知识点和材料表单 → 带关联的课程快照 |
| 版本发布 | `POST /courses/{course_id}/materials/{material_id}/revisions` → [RAGService.ingest](../../src/enterprise_rag/core/service.py) → [PostgresStore](../../src/enterprise_rag/adapters/postgres.py) | 带类型的材料和原始文件 → 文档版本、索引 ID 和 Chunk 数，历史版本仍可按授权读回 |

| 评测导出 | `enterprise_rag.evaluation archive` → [文件清单](../../src/enterprise_rag/evaluation/artifacts.py) → [评测路由](../../src/enterprise_rag/apps/course_rag/evaluations.py) | 已完成且经审阅的运行目录 → 限定文件名、大小和 SHA-256 的 ZIP，以及指标展示 |

V0.4 涵盖目录新增、浏览和版本发布。多用户授权、目录编辑删除、OCR、公开部署和正式保留集由后续需求决定。EnterpriseAgent 业务应用属于 V0.5。

## 技术决策与风险

- 用户指示继续下一阶段。Codex 按路线图推进 V0.4，采用独立应用 ID 和每课一个服务端派生的集合。可共用 PostgreSQL 实例或配置独立连接串。SQL 角色持有课程目录的读取与插入权限。独立的课程 API 与 UI 使用单个本地操作者令牌，令牌覆盖此应用的全部课程，故两端绑定回环地址。[课程迁移](../../migrations/course_rag/004_catalog.sql)
- Codex 选择用材料 UUID 生成稳定的核心文档名，并由共享入库事务发布修订。这让课程目录可直接读取当前版本，减少维护额外发布状态的成本。模型、切分或 Embedding 修订改变时，演示流程可新建课程并重新入库。
- Codex 选择 Streamlit 原生控件，前端只负责目录、问答与来源展示。PDFium 渲染单页，Pillow 叠加已核对的坐标。渲染时序列化访问 PDFium，限制输出尺寸。异常坐标回退整页，渲染失败保留原文。对大文件、复杂页面与多个并发用户仍需另外评估。[依赖与许可](../open_source_references.md#v04-应用依赖)
- 复用已有 V0.3 A–D 归档，支持后续已完成运行生成新清单。开发集的 40 个组别结果含 12 个结构化输出错误。此次功能验收也观察到模型输出波动。毕设正式比较仍需独立题集、人审和失败分析。[V0.3 开发集报告](../evaluation_runs/course-dev-20261120/report.md)

## 运行与测试

环境为 macOS ARM64、CPython 3.11.15、PostgreSQL 17.12 / pgvector 0.8.7、Ollama 0.23.1。真实模型为 Qwen 3.5 9B、nomic-embed-text 768 维和固定 BGE INT8。数据使用仓库自编演示材料。

- 在已有测试卷应用并重跑 `004_catalog.sql`，确认运行角色有 SELECT 与 INSERT 权限。Compose 另从空数据卷初始化迁移。
- `uv run --locked --extra course pytest -m 'not live'` 通过 71 项，覆盖旧版核心契约和 6 项 CourseRAG 回归，包括材料修订、授权隔离、PDF 高亮和旋转页回退、归档哈希校验以及 Streamlit 换课。`uv lock --check`、`uv build --wheel`、`docker compose config --quiet` 均通过。
- 使用本地模型与 BGE，`RAG_RUN_LIVE=1 uv run --locked --extra course --extra rerank pytest -m live` 通过 5 项，含新增 CourseRAG 端到端测试和 4 项共享核心回归。独立 API 用 HTTP 验证了导入双课程、操作系统 PDF 第 2 页高亮、跨课原文 404、空课程 `no_candidates` 和评测 ZIP 完整性。浏览器工作台返回了相同的 LRU 结论，显示对应陈述编号和页码。网络课程 API 返回练习链路 IP MTU 为 1500 字节，原文定位到第 7 行。
- 在同一测试配置中询问「根据课程笔记，LRU 选择哪个页面？」时，模型语义审阅返回无效 JSON，API 正确返回 `502 invalid_generation`。将问题写明确为「在 LRU 页面置换算法中，优先淘汰哪个页面？」后完成验证。模型问题及推理故障需按请求 ID 排查。
- 对 V0.3 归档副本运行 `archive` 与 `summarize`，复算指标文件与归档逐字节一致。GitHub 托管 CI 待分支发布后触发。

## 考后接手与贡献

先按 [本地演示](../course_rag_demo.md) 导入 PDF，沿问答响应的陈述、引文偏移和版本 ID 回读原文，再跟踪课程目录到共享核心的 scope 传递，最后复算一份归档。适合亲自完成的小改动包括添加一份有授权的课程讲义及标注，或为一类非标准 PDF 增加回退样例并记录结果。

| 执行者 | 状态 | 贡献与证据 |
| --- | --- | --- |
| 用户 | 已提供 | 指示继续开发，提供项目范围与仓库协作要求 |
| Codex | 已完成 | 编写并验证本提交的课程 API、界面、迁移、样例、归档导出及阶段测试 |
| 用户 | 计划考后完成 | 独立复现实例并提交标注或 PDF 回归，通过实际改动和运行记录核验 |
