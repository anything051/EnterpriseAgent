## 工程决策

- 用户指示推进既定 V1.0。Codex 选择本机 Docker Compose 发布方式。课程库只应用核心和课程迁移，企业库只应用核心、合成业务和会话迁移。应用与界面容器使用固定的非 root UID、只读根文件系统和回环宿主端口。原先的本机开发 Compose 继续可用。
- 课程和企业界面均要求操作者输入对应令牌，避免复用进程环境中的课程凭据。企业 SQL 继续由独立只读账号访问固定模板。应用日志记录受控方法、路由模板、请求 ID、状态与延迟。对无法匹配的 Host、请求内容和异常统一处理。
- 备份以 `pg_dump` 保存两个应用各自的数据，SHA-256 验证后能还原到另一个 Compose 项目的全新数据库。用原企业角色令牌恢复会话所有权，数据库密码可轮换。保持原 Embedding 端点与修订用于验证已有索引。
- Docker 路径在 macOS Docker Desktop 的 Linux arm64 容器验证。原生 Linux 宿主机的模型地址配置、GitHub 托管 CI、公开 TLS 入口和高并发生产负载尚未实测。当前无自动共库拆分命令，已有共库数据可保留原开发方式，迁移时按授权范围分别导出。

## 验证

- `uv run --locked --extra course --extra agent --extra rerank pytest -m 'not live'` 通过 90 项。锁文件、wheel 构建和 Compose 配置通过。
- 全新 Compose 双库启动后，使用真实模型执行 11 项端到端检查，全部通过。Streamlit 两个入口也用 AppTest 连接实际发行 API，核对课程登录和企业历史报告、角色切换。隔离检查确认企业只读角色可读取销售表且无业务写权限。请求测试标记和临时凭据未出现在发行 API 日志。[发行验收报告](../evaluation_runs/release/v1.0.0/report.md)
- 分别备份课程库与企业库，在使用新数据库密码的独立项目还原。6 项恢复验收全部通过，包括原 PDF 预览的哈希、Markdown 原文、原企业会话及报告哈希、恢复后使用已建索引重新问答。脚本拒绝原项目和已有目标库。恢复后回切原项目验证同一原文及报告仍可读。[恢复记录](../evaluation_runs/release/v1.0.0/restored.json) · [回切记录](../evaluation_runs/release/v1.0.0/switchback.json)
- V0.3 A–D、V0.5 E0/E1 与 V0.6 E1/E2 的汇总指标均能从归档样本复算。课程的正式毕设效果仍需独立保留集和人工标注复核。
