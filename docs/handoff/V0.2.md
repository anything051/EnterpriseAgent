## 决策与风险

- 用户指示继续下一阶段。Codex 沿路线图进入 V0.2，保留 `vector/off` 作为 V0.1 对照。候选分支上限 20，RRF 常数 60，审阅最多检查排序后的 10 条。BM25 在同一 PostgreSQL 快照内计算，超过 5,000 个活动 Chunk 时明确退回向量检索。词法排序按请求重建，适合当前小语料。
- 原计划的 CrossEncoder 改用固定版本的 BGE INT8 ONNX，保留成对打分并降低本地依赖体积。权重与分词器 SHA-256 由代码校验。本机模型目录为忽略提交的 `.rag-models/bge`。可选模型缺失、运行失败或达到默认 8 秒请求预算时退回 RRF。进程内超时会结束等待，无法确保立即中断模型初始化或操作系统 I/O。[组件与许可](../open_source_references.md)
- 证据支持性和问题覆盖走两次结构化审阅。合并提示的实测出现过引用编号混淆和遗漏子问题。拆开后将引用限定为已授权原文，并要求覆盖审阅逐个标记草稿里的对应陈述。语义和覆盖判断仍可能误判，V0.3 应用人工标注复核。开启审阅会增加推理调用和用量。
- PDF 坐标只在原始字形顺序与保存文本一致时使用。旋转、裁切、非标准物理单位和异常页盒会回退。V0.1 解析与向量配置保持兼容。迁移允许应用通过限范围函数读取原件，应用角色仍无原件表内容列的直接读取权限。

## 实际验证

使用 macOS ARM64、CPython 3.11.15、PostgreSQL 17.12 / pgvector 0.8.7、Ollama 0.23.1、Qwen 3.5 9B、nomic-embed-text 768 维及 BGE INT8。仅用自编与合成样例进行开发验收。

- 对既有 V0.1 测试卷执行 `003_highlight_source.sql` 通过，抽查 V0.1 已入库的课程 PDF，无需重建索引即可进行词法检索和高亮。另用空 Compose 卷验证自动迁移及应用账号权限。
- `uv run --locked --extra rerank pytest -m 'not live'` 通过 56 项，覆盖对照基线、精确术语、同快照、重排降级、无引用、不完整回答、冲突和 PDF 几何回退。
- 配置本地模型和 `RAG_RERANKER_DIR=.rag-models/bge`，执行 `RAG_RUN_LIVE=1 uv run --locked --extra rerank pytest tests/unit tests/integration`，60 项全部通过（39 单元、17 数据库集成、4 真实模型）。实测包含本地 BGE 重排、跨段支持、同范围冲突、遗漏负责人子问题和 V0.1 基线回归。
- 在课程 PDF 样例的单次运行中，支持性审阅使用 501/100 输入/输出 Token，覆盖审阅使用 165/42。这是功能验收的样例用量。
- 用 Poppler 渲染课程 PDF 第 2 页，叠加 PDF 接口计算的 25 个字符框，目视核对 LRU 证据行。范围与原文切片一致。
- `uv lock --check`、wheel 构建、文档链接及 Git 差异检查已验证。正式的 A–D 对照属于下一阶段。
